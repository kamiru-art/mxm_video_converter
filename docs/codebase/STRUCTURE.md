# Codebase Structure

## 1) Top-Level Map

| Path | Purpose | Evidence |
|------|---------|----------|
| `rust-core/` | The image processing core. Rust, compiled to WebAssembly. No browser code. | `rust-core/Cargo.toml` |
| `rust-core/src/` | 18 domain modules plus the WebAssembly boundary. | `rust-core/src/lib.rs` |
| `rust-core/assets/` | `DejaVuSans.ttf`, embedded with `include_bytes!`, and its license notice. | `rust-core/src/text.rs` |
| `rust-core/tests/` | The end-to-end integration test. | `rust-core/tests/pipeline.rs` |
| `web/` | The web application. No framework. | `web/package.json` |
| `web/src/` | The interface, the worker pool and the video pipeline. | `web/src/main.js` |
| `web/src/wasm/` | Generated by `wasm-pack`. Not in version control. | `web/.gitignore` |
| `web/public/` | Static files served as they are: the service worker, the manifest, the icons. | `web/public/sw.js` |
| `assets/` | The application icons. | `assets/icon.png` |
| `.github/workflows/` | One workflow: test, then build, then deploy. | `.github/workflows/ci.yml` |
| `docs/codebase/` | These documents. | this file |

## 2) Entry Points

- Main runtime entry: `web/index.html`, which loads `web/src/main.js`.
- `web/src/main.js` mounts one phase module on demand and keeps the route in
  `location.hash`.
- Worker entry: `web/src/worker.js`. The pool starts it with
  `new Worker(new URL('./worker.js', import.meta.url), { type: 'module' })`
  (`web/src/pool.js`).
- WebAssembly entry: `rust-core/src/api.rs`. It holds the 25 `#[wasm_bindgen]`
  functions and is the only module the JavaScript side calls.
- Test entry: `web/e2e.html` with `web/src/e2e.js`, driven by `web/e2e-run.mjs`.
- Build-time entry: `web/prepare-ffmpeg.mjs` copies the ffmpeg core out of
  `node_modules` into `web/public/ffmpeg/`. `npm run dev` does not run it.

## 3) Module Boundaries

| Boundary | What belongs here | What must not be here |
|----------|-------------------|------------------------|
| `rust-core/src/` domain modules (`sheet`, `scanproc`, `cyanotype`, `aruco`, `qr`, `calib`, `geometry`, `img`, `imgproc`, `codecs`, `dedup`, `pdf`, `text`, `layoutfile`) | Pure image and geometry work. Plain Rust types. | `wasm_bindgen`, browser types, input and output. |
| `rust-core/src/api.rs` | The WebAssembly boundary: argument validation, JSON to typed values, `Result<_, JsValue>`. | Image algorithms. |
| `web/src/pool.js` | Worker lifetime, dispatch, memory recycling. | Anything about the interface. |
| `web/src/worker.js` | A command name to core function table. | Business rules. |
| `web/src/phase*.js` | The DOM of one phase and its event handling. | Direct WebAssembly calls; everything goes through `run()`. |
| `web/src/project.js` | The state shared between phases, in memory. | Persistence. |
| `web/src/store.js` | The only `localStorage` reader and writer. | Anything else. |

## 4) Naming and Organization Rules

- Rust files: `snake_case.rs`, one module for each domain area
  (`scanproc.rs`, `cyanotype.rs`). Declared in `rust-core/src/lib.rs`.
- JavaScript files: lowercase, no separator, with a number for the phases
  (`phase1.js`, `pool.js`, `webgpu.js`).
- Each phase module exports one `mount<Name>` function that receives its root
  element: `mountPhase1(rootEl)` (`web/src/main.js`).
- Organisation is by workflow phase, not by layer or by type. Phase 1 is the
  sheets, phase 2 the scans, phase 3 the calibration, phase 4 the video. The
  route names do not follow the numbers: `sheets`, `scans`, `calibration`,
  `video`, `help` (`web/src/main.js`).
- Imports are relative, with the `.js` extension. There is no alias and no
  barrel file.
- The old Spanish routes still resolve, through the `LEGACY_ROUTES` table in
  `web/src/main.js`, so that saved links keep working.
